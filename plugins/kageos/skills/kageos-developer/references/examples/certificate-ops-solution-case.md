# 方案案例：证书自动化运维管家

## 解决什么问题

证书管理的痛点不是“存一张证书表”，而是生命周期风险：域名多、到期容易忘、DNS 验证步骤繁琐、失败缺少记录、签发后的文件需要归档和追踪。

这个方案把证书从一次性脚本变成可审计的运维系统：配置可管理、域名可跟踪、申请有记录、资产可下载、续期能自动巡检、失败能通知负责人。

## 推荐目录能力

| 能力 | 类型 | 作用 |
| --- | --- | --- |
| 证书配置台账 | Table + Form | 管理供应商配置、账号邮箱、启用状态、最近测试结果；敏感字段隐藏或业务侧加密 |
| 域名证书台账 | Table | 管理主域名、SAN、负责人、通知人、自动续期、提前续期天数、当前状态 |
| 证书申请记录 | Table | 记录首次签发、手动续期、自动续期的状态、错误、DNS 验证信息和资产关联 |
| 证书资产库 | Table | 归档证书文件、私钥、证书链、过期时间、剩余天数和下载入口 |
| 申请/续期证书 | Form | 人工触发一次签发或续期，执行 DNS-01、等待验证、归档文件 |
| 自动续期巡检 | Form + 默认调度 | 每天检查启用自动续期且即将过期的域名，自动签发并归档 |
| 风险日报 | 定时会话 | 汇总即将过期、已过期、失败请求、负责人分布和处置建议 |

## 关键业务设计

- 长流程要有申请记录表，状态从待执行、执行中、等待 DNS、生效验证、成功或失败逐步更新。
- 同一域名要避免并发申请；提交前检查是否已有执行中的请求。
- 签发或续期成功后创建新的资产记录，保存证书、私钥、证书链、fullchain、打包文件等可下载 file 引用；不要只把文件作为本次 Form 输出返回。
- 域名台账可记录当前资产 ID 或最新到期时间，但不要直接覆盖历史证书资产，便于回滚和审计。
- 失败要记录错误信息，并通知负责人或通知人；通知失败不应破坏主流程状态。
- 自动续期只处理启用、允许自动续期、达到提前续期阈值的域名。
- 自动续期不是延长旧证书，而是提前签发一张新证书；旧证书在到期前仍可用，业务服务需要部署新证书后才会切换。
- 系统可以管理和归档证书文件，但不要默认自动部署到业务服务器。自动部署应做成单独能力，明确目标类型、鉴权、回滚和重载策略后再接入。

## 无人值守怎么做

自动续期适合写成默认调度 Form：例如每天凌晨巡检所有启用域名，发现未签发或剩余天数低于阈值就自动走签发流程。它是稳定、可重复、参数固定的后台动作。

风险日报适合写成定时会话：每天读取域名台账、申请记录和资产库，输出“即将过期”“失败请求”“负责人 TOP”“需要人工处理”的 Markdown 摘要。它比普通 Form 更适合做跨表总结和运营建议。

## 模型应该学到的格局

不要只写“申请证书表单”。证书系统是一个运维闭环：

- 配置让系统知道怎么操作外部 DNS。
- 域名台账让系统知道管理范围和责任人。
- 申请记录让每次执行可追踪、可排错。
- 资产库让产物可下载、可回溯。
- 默认调度让续期无人值守。
- 风险报告让负责人知道哪里需要介入。

这个模式也能迁移到云资源巡检、域名备案、备份校验、账单预警、机器人 Token 轮换等运维场景。
