### 1.2 已有的"通用型"工具（run_command 模式）

这些是「一个工具能干 N 件事」的利器，LLM 可以自由拼命令：

| 工具 | 底层能力 | 通用度 |
|------|----------|--------|
| run_gm_command | GraphicsMagick：任意图片处理 | ★★★★★ |
| run_ffmpeg_command | FFmpeg：任意音视频处理 | ★★★★★ |
| run_gs_command | Ghostscript：任意 PDF 处理 | ★★★★ |
| run_poppler_command | Poppler：PDF→文本/图片 | ★★★★ |
| run_graphviz_command | Graphviz：任意 DOT 渲染 | ★★★ |
| run_libreoffice_command | LibreOffice：任意文档格式互转 | ★★★★★ |
| run_pandoc_command | Pandoc：Markdown/HTML/docx 互转 | ★★★★ |
| run_tesseract_command | Tesseract：任意 OCR | ★★★★ |
| python_execute | Python：任意计算/数据处理 | ★★★★★（万能后备） |
| lua_execute | Lua：轻量脚本 | ★★★ |

**关键认知**：`run_command` 模式是底层"万能钥匙"，但它对 LLM 来说**认知负担重**（要知道怎么拼命令）。**专用函数**是面向场景的"快捷键"，tags 精准、参数清晰，LLM 搜到即用。所以策略是：**高频场景做专用函数，长尾场景靠 run_command 兜底**。

## 四、新增函数建议（按优先级排序）

### 第一梯队：覆盖面最广、用户感知最强（P0）

#### 1. 🎵 `audio/ffmpeg` — 音频处理（新增包）

> **理由**：音频是完全空白领域，但底层工具 FFmpeg 已经有了！只需新增几个专用 Form。

| 函数名 | 能力 | 通用性 | 实现方式 |
|--------|------|--------|----------|
| **audio_convert.form** | 音频格式转换（MP3/WAV/FLAC/AAC/OGG/M4A 互转） | ★★★★★ | ffmpeg -i {{input}} -acodec xxx {{output}} |
| **audio_extract.form** | 从视频提取音频（视频→MP3/WAV） | ★★★★★ | ffmpeg -i {{input}} -vn -acodec xxx {{output}} |
| **audio_trim.form** | 音频剪切（指定开始/结束时间） | ★★★★ | ffmpeg + -ss -to |
| **audio_merge.form** | 多个音频合并为一个 | ★★★★ | ffmpeg concat |
| **audio_info.form** | 提取音频信息（时长、码率、采样率等） | ★★★ | ffprobe |

**注意**：`run_ffmpeg_command` 已经能做所有这些，但 tags 是"视频"相关的。用户搜"音频转换""提取音频"搜不到。**专用函数的意义就是让 search_tools 能搜到。**

#### 2. 📱 `qrcode` — 二维码生成与识别（新增包）

> **理由**：几乎所有用户都会用到，实现简单，感知极强。

| 函数名 | 能力 | 通用性 | 实现方式 |
|--------|------|--------|----------|
| **qrcode_generate.form** | 文本/URL → 二维码图片（支持尺寸、颜色、Logo嵌入） | ★★★★★ | Go 库 `skip2/go-qrcode` 或 Python `qrcode` |
| **qrcode_read.form** | 图片 → 识别二维码内容 | ★★★★ | Go 库 `makiuchi-d/gozxing` 或 Python `pyzbar` |
| **barcode_generate.form** | 生成条形码（EAN-13、Code128 等） | ★★★ | Go 库 `boombuler/barcode` |

#### 3. 📄 `pdf` — PDF 专用高频操作（在 gs 或新包下）

> **理由**：PDF 合并/拆分/加水印是办公刚需中的刚需。现有 gs run_command 能做但太通用，搜不到。

| 函数名 | 能力 | 通用性 | 实现方式 |
|--------|------|--------|----------|
| **pdf_merge.form** | 多个 PDF 合并为一个 | ★★★★★ | gs 或 Go 库 `pdfcpu` |
| **pdf_split.form** | 按页码范围拆分 PDF | ★★★★★ | gs 或 `pdfcpu` |
| **pdf_add_watermark.form** | PDF 加文字/图片水印 | ★★★★ | `pdfcpu` |
| **pdf_encrypt.form** | PDF 加密（设置打开密码） | ★★★ | `pdfcpu` |
| **pdf_page_extract.form** | 提取 PDF 指定页面 | ★★★★ | gs 或 `pdfcpu` |
| **images_to_pdf.form** | 多张图片→拼成一个 PDF | ★★★★★ | Go 库 `jung-kurt/gofpdf` 或 Python |

#### 4. 🔧 `encoding` — 编码/Hash/转换工具（新增包）

> **理由**：开发者日常高频工具，实现极其简单（纯 Go 标准库），投入产出比最高。

| 函数名 | 能力 | 通用性 | 实现方式 |
|--------|------|--------|----------|
| **base64_codec.form** | Base64 编码/解码（文本或文件） | ★★★★★ | Go 标准库 `encoding/base64` |
| **hash_generate.form** | 计算文件/文本的 MD5、SHA1、SHA256 | ★★★★★ | Go 标准库 `crypto/*` |
| **url_codec.form** | URL 编码/解码 | ★★★★ | Go 标准库 `net/url` |
| **timestamp_convert.form** | 时间戳 ↔ 日期时间互转（支持多时区） | ★★★★★ | Go 标准库 `time` |
| **text_encoding_convert.form** | 文本编码转换（GBK/GB2312/Big5 ↔ UTF-8） | ★★★★ | Go `golang.org/x/text` |

**这类工具可以考虑做一个"通用型"**：

| 函数名 | 能力 | 说明 |
|--------|------|------|
| **text_transform.form** | 通用文本转换器 | 参数 `operation`（base64_encode/base64_decode/url_encode/url_decode/md5/sha256/to_upper/to_lower/trim...），一个函数顶 10 个 |

但 **tags 要覆盖所有关键词**，否则搜不到。或者两种都做：一个通用 + 几个专用高频。

## 五、通用 vs 专用策略总结

```
                        搜索可发现性
                            ↑
    ┌───────────────────────┼───────────────────────┐
    │  专用函数（image_compress）                     │
    │  ✅ tags 精准，搜"图片压缩"直达                  │
    │  ✅ 参数清晰，LLM 直接填                        │
    │  ❌ 一个场景一个函数，数量多                      │
    │                       │                       │
    │  通用函数（run_gm_command）                      │
    │  ⚠️ tags 覆盖有限，长尾搜不到                     │
    │  ⚠️ LLM 需要知道命令怎么拼                       │
    │  ✅ 一个函数覆盖 100 个场景                       │
    └───────────────────────┼───────────────────────┘
                        灵活度/覆盖面
```

**推荐策略**：
- **每个工具链保留一个 run_command 通用兜底**（已有 gm/ffmpeg/gs/poppler/pandoc/libreoffice/graphviz/tesseract）
- **Top 3~5 高频场景做专用函数**（让 search_tools 搜得到、LLM 用得好）

## 八、关键结论

1. **最大的空白是音频**：FFmpeg 已经在容器里了，只是缺"音频"相关的专用函数和 tags，搜"音频"完全搜不到。这是投入最低、回报最高的补充。

2. **编码/Hash/时间戳** 类工具实现极简（纯 Go 标准库，几十行代码），但开发者使用频率极高，属于"不做说不过去"的基础工具。

3. **二维码** 是那种"谁都能用到、用一次就觉得这平台牛逼"的功能，而且实现简单。

4. **PDF 合并/拆分** 是办公刚需的天花板，现有 `run_gs_command` 能做但普通用户搜不到、不会拼命令。

5. **图片专用函数**（格式转换/缩放/压缩）和 `run_gm_command` 的关系就像你说的——`run_gm_command` 是通用版，但要让 search_tools 对"图片压缩""图片格式转换"这些关键词命中，就得做专用函数。

6. **Python Execute 是终极兜底**：理论上 Python 能做一切，但它的 tags 太泛了。专用函数的核心价值在于 **tags 精准 → search_tools 命中 → LLM 能找到 → 用户体验好**。
