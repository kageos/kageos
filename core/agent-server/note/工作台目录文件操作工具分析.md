# 工作台目录文件操作工具分析

参考「update app 链路」：希望工作台能**充分操作目录**，具备：**读目录文件、写目录文件、删除目录文件、编辑目录文件**。以下为现状与可行性分析。

---

## 一、当前能力一览

| 能力 | 现状 | 对应工具/链路 |
|------|------|----------------|
| **读目录文件** | ✅ 已有 | `read_go_file`（代码）、`read_doc`（文档）、`read_dir`（目录结构） |
| **写目录文件** | ✅ 已有 | `write_go_file`、`write_doc` |
| **删除目录文件** | ❌ 缺失 | 无 `delete_file`；app-server 有 DeleteFunction 但只删 DB，不删磁盘 |
| **编辑目录文件** | ✅ 可等价实现 | 读 + 改内容 + 写（无单独 `edit_file` 工具） |

---

## 二、读目录文件（已有，且已支持实时读 runtime）

- **read_go_file**：通过 `apicall.GetWorkspaceContext(directory, "runtime")` 拿目录下**代码文件列表 + 内容**。  
  - **file_source=runtime**：app-server 调 app-runtime `ReadDirectoryFiles`（从磁盘实时读），保证内容与当前磁盘一致；失败时回退到快照。  
  - **file_source 默认/空**：app-server 使用 `FileSnapshotRepository.GetCurrentSnapshotsByDirectory`（快照表，可能不准）。  
  - 工作台 **read_go_file** 已使用 `file_source=runtime`，即**实时读 runtime 目录文件**。
- **read_doc**：按 `directory`（full_code_path）读文档节点正文（内置或工作区）。
- **read_dir**：读目录下子节点（package/function）+ 可选递归、可选包含文件列表；`include_code=true` 时也会带文件内容（本质仍走 GetWorkspaceContext）。

结论：**读**已覆盖「目录下的代码文件 + 文档」，与 update app 链路的「可读目录文件」一致。

---

## 三、写目录文件（已有）

- **write_go_file**：  
  - agent-server：`RunAddFunctionsTool` → `apicall.ServiceTreeAddFunctions`。  
  - app-server：`AddFunctions` → `ProcessFunctionGenResult` → `UpdateApp(CreateFunctions)`。  
  - app-runtime：`CreateFunctionService` 写磁盘 + 可选编译/部署（与 update app 链路一致）。
- **write_doc**：创建/更新文档节点（CreateDocs/UpdateDocs），不涉及代码目录磁盘。

结论：**写**已支持「在指定目录下写 .go 文件」并走完整编译链路；若未来要写非 .go（如 .yaml），需扩展 BatchWriteFiles/AddFunctions 支持类型或新增接口。

---

## 四、删除目录文件（缺失，需补齐）

- **现状**：  
  - app-server 有 `DeleteFunction(id)`、`DeleteServiceTree(id)`，仅删 DB 中的节点，**未**通知 app-runtime 删磁盘文件。  
  - app-runtime 仅在「回滚」时按已写路径删文件，没有对外「按路径/按 function 删单文件」的 API。
- **影响**：工作台无法真正「删除目录下某个文件」，只能删节点，磁盘会留脏文件。
- **建议**：  
  1. **app-runtime**：新增「按 full_code_path + file_name 删除磁盘文件」的接口（或复用现有回滚逻辑封装为「删单文件」），并在删除后视需要做编译/版本更新。  
  2. **app-server**：在 `DeleteFunction` 时调用 app-runtime 删磁盘文件（或先 app-runtime 再删 DB），保证节点与磁盘一致。  
  3. **agent-server**：新增工具 `delete_file`，参数如 `directory`、`file_name`，内部解析为 full_code_path + 文件名，调 app-server 删除对应 function 节点（并触发 app-runtime 删文件）。  
  4. 若希望「只删文件不删节点」：需在 app-server/app-runtime 增加「仅删磁盘文件」的能力，再通过工具暴露（一般更推荐「删节点 = 删文件」一致语义）。

结论：**删除**需要补齐「app-runtime 删磁盘 + app-server 删节点联动 + 工作台 delete_file 工具」。

---

## 五、编辑目录文件（已有等价能力，可选增强）

- **现状**：  
  - 无单独 `edit_file` 工具。  
  - 模型可先 `read_go_file(directory, file_name)` 拿到内容，再改内容，再 `write_go_file(directory, file_name, content)`，即等价于「编辑」。
- **可选增强**：  
  - 新增 `edit_file(directory, file_name, content)`：语义为「用 content 覆盖该文件」，内部实现为「写该路径」（与 write_go_file 同链路），仅减少模型一步「先 read 再写」的显式调用，便于提示词里写「编辑用 edit_file」。  
  - 不新增也可：在提示词中明确「编辑 = read_go_file 后修改内容再 write_go_file」。

结论：**编辑**当前可用「读+写」完成；是否加 `edit_file` 属体验优化，非必须。

---

## 六、与 update app 链路的对齐情况

| update app 链路能力 | 工作台是否具备 | 说明 |
|---------------------|----------------|------|
| 读取目录文件        | ✅ 具备         | read_go_file / read_doc / read_dir |
| 写目录文件          | ✅ 具备         | write_go_file → AddFunctions → UpdateApp(CreateFunctions) |
| 删除目录文件        | ❌ 不具备        | 缺 delete_file，且 app 侧未实现「删节点同时删磁盘」 |
| 编辑目录文件        | ✅ 具备（读+写） | 可加 edit_file 便捷工具 |

---

## 七、推荐落地顺序

1. **删除目录文件（必做）**  
   - app-runtime：支持「按目录+文件名删除磁盘文件」并在需要时触发编译/版本。  
   - app-server：DeleteFunction 时调用 app-runtime 删文件，再删 DB。  
   - agent-server：新增 `delete_file(directory, file_name)`，按 full_code_path + file_name 解析为对应 function 并调用删除接口。

2. **编辑目录文件（可选）**  
   - 在 agent-server 增加 `edit_file(directory, file_name, content)`，内部复用 write_go_file 链路（同一目录+文件名+新 content 即覆盖），并在提示词中说明「编辑用 edit_file 或 read+write」。

3. **读/写扩展（按需）**  
   - 若需「读/写非 .go、非文档」文件（如配置）：再考虑扩展 GetWorkspaceContext/FileSnapshot 或 BatchWriteFiles 支持的类型，并对应扩展 read_go_file/write_go_file 或拆成 read_file/write_file。

---

## 八、小结

- **读、写、编辑**：工作台已能充分覆盖「读目录文件、写目录文件、编辑目录文件」（编辑=读+写）。  
- **删除**：是当前缺口，需要从 app-runtime → app-server → agent-server 打通「删节点且删磁盘」并暴露为 `delete_file`，工作台即可与 update app 链路一样**充分操作目录**。

完成上述删除能力后，即可做到：**读目录文件、写目录文件、删除目录文件、编辑目录文件** 四条能力齐全。
