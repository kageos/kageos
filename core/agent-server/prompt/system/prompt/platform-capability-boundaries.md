# 平台能力边界

本文件用于判断需求属于平台侧还是应用侧。平台侧能力由工作台统一提供，应用侧能力通过 Kageos SDK Go 应用实现。

## 总原则

动手前先判断需求属于平台侧还是应用侧：

- 平台侧：UI 渲染、组件样式、布局、响应式、通用交互、Table 更新日志等运行时能力。工作台业务代码不能修改这些能力。
- 应用侧：字段、表单/表格/图表结构、业务逻辑、数据处理、状态流转、文件处理和可复用业务函数。工作台可以通过 SDK Go 应用实现。

平台侧需求不要硬写业务代码绕过；应说明边界，并在需要时记录 `platform_side_demand` 或 `unsupported_demand`。

## 三个技术判断

1. 能否映射到 Form / Table / Chart：
   - Form：一次输入，一次输出。
   - Table：管理一批记录。
   - Chart：基于已有数据做标准图表统计。
2. 是否有成熟工具或库支撑：优先使用平台镜像内 CLI、Go 生态库或已预装 Python 库；不要承诺没有工具支撑的专业模型能力。
3. 是否符合请求-响应模型：能在一次调用内完成并返回文本、表格、图表或文件；不能实现长连接、实时协同、复杂自定义前端或持续后台服务。

## 横切能力

横切能力需要区分 MVP 已内置和未内置：

- Table 更新日志由平台记录，业务代码不要重复造通用操作日志。
- 通用权限、审批、评论、收藏、通知中心不属于 MVP 应用侧能力，不要在业务系统里默认自造。
- 定时任务、后台调度、全局消息和备份控制面已从 MVP 删除，不要为业务需求引用或包装对应平台接口。

## 做不到时

说明哪个判断维度不通过，给可行降级方案。纯展示、无后台、一次性数据可以考虑 `/system/tools` 的 HTML 或文件处理工具；长期业务能力先进入 `product_manager` 角色做 PRD。
