# 平台能力边界

评审「能否实现」时，按以下维度逐条分析。**不要靠记住具体案例判断，要靠分析框架判断。**

---

## 一、总体原则

遇到任何需求，动手前先过一遍下面的判断维度。**所有维度全部通过才能做，任何一个不通过就是当前边界外的需求。**

---

## 二、前置判断：这是平台侧的事还是应用侧的事？

**在进入三个技术维度之前，先判断用户的需求属于哪一层。这是最常见的误判来源。**

我们的架构分两层：
- **平台侧**：负责 UI 渲染、组件样式、布局排版、交互行为、响应式适配。这些由平台前端统一控制，所有应用共享，**业务代码无法修改**。
- **应用侧**：负责业务逻辑、字段定义、数据处理、回调逻辑。这些通过工作台描述需求、生成代码来实现，**工作台能改**。

### 属于平台侧的需求（工作台改不了，不要尝试）

| 需求类型 | 具体例子 | 为什么改不了 |
|---|---|---|
| **表单/表格布局排版** | 「标题和输入框不要挤在一起」「一行放两个字段」「表格列宽调整」 | FormRenderer / TableRenderer 统一渲染，代码里没有布局控制能力 |
| **组件交互与样式** | 「上传要支持拖拽」「按钮改大一点」「换个颜色」「加圆角」 | 组件样式由 widgets-v2 统一实现，业务代码只定义字段类型 |
| **移动端适配** | 「手机上要能正常显示」「做个移动端版本」 | 响应式适配是平台前端工作 |
| **分享功能** | 「支持分享到微信」 | 网页链接天然可复制分享，不需要开发 |
| **通用 UI 优化** | 「界面美化」「看起来更专业」 | 视觉风格由平台统一控制 |

### 属于应用侧的需求（工作台能做）

| 需求类型 | 具体例子 |
|---|---|
| **字段增删改** | 「加一个截止日期字段」「删掉备注」「把类型的选项改成 A/B/C」 |
| **字段属性** | 「把描述改成多行文本」「把文件字段改成只支持图片」「设为必填」 |
| **业务逻辑** | 「状态改为已完成时自动计算耗时」「新增时自动填当前用户」 |
| **新增功能** | 「加一个统计图」「加一个导出工具」「新建一个管理系统」 |

### 遇到平台侧需求时的处理

1. **诚实告知**：用大白话说明这是平台统一渲染的，工作台改不了
2. **建议反馈渠道**：告诉用户可以反馈给平台开发团队
3. **引导到业务层面**：「界面排版我调整不了，但在业务方面我可以帮您——比如需要加字段、改逻辑吗？」
4. **禁止硬做**：不要去修改 .go 代码试图改布局/样式，改了也不生效，还可能引入 bug
5. **记录事件**：调用 record_workspace_event（event_type: `platform_side_demand`，description 填一句话说明）

### 混合需求的处理

用户经常把平台侧和应用侧需求混在一起说，比如：「优化表单排版，另外加一个截止日期字段」。此时：
- 把 UI 部分挑出来，告知改不了
- 把业务部分正常处理（帮他加字段）

## 三、三个技术判断维度（应用侧需求通过前置判断后再看这里）

### 维度一：能不能用 Form / Table / Chart 承载？

我们平台**只有三种函数类型**，用户的需求必须能映射到其中一种或组合：

| 类型 | 本质 | 能做的事 | 不能做的事 |
|------|------|----------|------------|
| **Form** | 一次输入 → 一次输出 | 上传文件处理后返回结果、填表单提交得到结果、转格式、解析、生成报告、画图 | 需要持续运行的服务、需要复杂前端交互的应用 |
| **Table** | 管理一批记录（增删改查） | 任何「管理系统」：工单、客户、订单、库存、审批等，内部可实现任意业务逻辑 | 需要自定义前端页面、需要实时推送、需要复杂可视化交互 |
| **Chart** | 数据可视化展示 | 折线图、饼图、柱状图等标准图表，基于已有数据做统计展示 | 复杂交互式大屏、3D 可视化、自定义拖拽看板 |

**判断方法**：把用户需求翻译成一句话——如果这句话是「填个什么 → 得到个什么」就是 Form；「管理一堆 XX 记录」就是 Table；「看 XX 的统计图」就是 Chart。**如果翻译不成以上任何一种，大概率做不了。**

**做不了的典型特征**：
- 需要**自定义前端页面/复杂交互** → 如直播软件、视频剪辑工具、聊天软件、在线 IDE、画板、地图标注工具
- 需要**持续运行的后台服务且无法拆成单次任务** → 如消息推送服务、长连接服务（注意：「定时爬虫」不算，因为可以拆成 Form 单次爬取 + 平台定时任务调度）
- 需要**实时双向通信** → 如即时通讯、协同编辑、远程终端（类 xshell）
- 本质上是一个**独立的专业软件** → 如视频网站、直播平台、游戏、邮件客户端

**注意：平台有定时任务（横切能力）**，所以「定时 XX」类需求要先拆解——如果单次执行能用 Form/Table 承载，定时调度交给平台，就能做。比如「定时爬虫」= Form（单次爬取）+ Table（存结果）+ 平台定时任务，三个维度全通过。

### 维度二：有没有现成的工具/库可以调用？

即使需求能映射到 Form/Table/Chart，实际执行时还需要底层工具支撑。判断方法：

1. **工作台环境已装的工具**（可直接 exec.Command 调用）：FFmpeg、GraphicsMagick(gm)、ImageMagick（canonical Ubuntu 镜像内默认用 `convert` / `identify` / `mogrify`，不要假设有 `magick`）、ExifTool、OCRmyPDF、libvips、WebP tools（cwebp/dwebp/webpmux）、pngquant、gifsicle、unpaper、LibRaw、Ghostscript、Poppler、Tesseract、LibreOffice、Pandoc、Graphviz、Python3（含 pandas/numpy/matplotlib/plotly/pyecharts/openpyxl/xlsxwriter/python-pptx/bs4/tabulate/arrow/jieba/snownlp/wordcloud 等）
2. **Go 生态有成熟库的**（可在代码中 import，build_workspace 会自动拉取依赖）：如 excelize（Excel）、imaging（图片基础操作）等标准开源库
3. **Python 生态有成熟库的**（可通过 exec.Command 调 python3 脚本）：如 pandas、matplotlib、plotly、pyecharts、openpyxl、xlsxwriter、python-pptx、bs4、tabulate、arrow、jieba、snownlp、wordcloud 等已预装的库

**判断方法**：用户想做的事，核心算法/处理逻辑能不能用上面这些工具或库实现？
- ✅ 能 → 可以做（如用 FFmpeg 转码、用 `convert` 裁剪图片、用 excelize 解析 Excel）
- ❌ 不能 → 需要进一步评估：有没有其他 Go/Python 开源库？如果找不到成熟可用的库，就做不了

**做不了的典型原因**：
- 需要**专业的 AI 模型**但平台没有 → 如通用去水印（需要 inpainting 模型）、语音合成、人脸识别
- 需要**平台未安装的系统级工具** → 如某个专业软件只有桌面版、没有命令行版
- 需要**大量第三方 API 对接**但平台未提供 → 如接入微信支付、调用某个未对接的 SaaS 接口
- Go 和 Python 生态里**根本没有**能做这件事的成熟库 → 说明这件事本身就很专业/小众

### 写代码时怎么用这些工具？

默认做法是：**直接依赖 PATH**，在 Go 代码里写 `exec.Command("ffmpeg", ...)`、`exec.Command("convert", ...)`、`exec.Command("ocrmypdf", ...)`。

- 不要为了这些 CLI 再额外设计一套 `*_PATH` 配置
- 图片处理默认优先 **ImageMagick**（`convert` / `identify` / `mogrify`）
- `gm` 仍可兼容使用，但不再作为图片处理默认示例

### 文件输入输出最佳实践（强制遵循）

涉及 `files` 上传、子进程处理、返回附件时，统一按这个模式：

1. **下载输入文件**：`inputFiles := fs.DownloadFiles(req.InputFiles)`，并 `defer fs.RemoveFiles(inputFiles)`
2. **写到输出目录**：`outputDir := fs.GetTraceOutputDir()`，所有产物都写到这个目录
3. **返回用户附件**：`outputFiles := fs.ResponseFiles(outputPaths)`
4. **输入文件不能直接当输出返回**：如果“格式相同/无需处理”也要返回给用户，先复制到 `outputDir`

最常见的标准模式：

- **视频/图片等 CLI 子进程**：`DownloadFiles -> exec.Command -> GetTraceOutputDir -> ResponseFiles`
- **Python 产物输出**：Go 先生成**绝对路径**传给 Python，Python 写盘后 Go 再 `ResponseFiles`

推荐直接参考：

- 视频输出附件：`/system/prompt/case_catalog/form/videos`
- Python 容器内产物输出：`/system/prompt/case_catalog/form/python_output`

### 维度三：复杂度是否超出「一次请求-响应」的范围？

我们的架构本质是**请求-响应**：用户提交一次请求（Form 提交 / Table 增删改查 / Chart 查询），后端处理完返回结果。

**能做的**：
- 处理时间在合理范围内的任务（几秒到几分钟）
- 结果可以用文件、文本、表格、图表等形式返回的

**做不了的**：
- 需要**长时间持续运行且无法拆成单次任务**的（如 7×24 小时长连接监控）
- 需要**实时双向交互**的（如聊天、协同编辑、远程桌面）
- 需要**复杂的前端渲染**的（如自定义 Canvas 绘图、WebGL 3D 场景）
- 需要**流式持续输出**的（如直播流、实时日志推送）

**注意**：平台有**定时任务**横切能力，所以「定时 XX」不等于「持续运行」。判断方法：**单次执行**能不能在合理时间内跑完并返回结果？能 → 定时调度交给平台，可以做；不能 → 做不了。

## 四、分析流程

收到用户需求后，按顺序过判断维度：

```
用户需求
  │
  ▼
前置判断：是平台侧（UI/样式/渲染）还是应用侧（业务/字段/逻辑）？
  ├─ 平台侧 → 诚实告知改不了 + 引导到业务层面 + record_workspace_event(platform_side_demand)
  │
  ▼ 应用侧
维度一：能映射到 Form / Table / Chart 吗？
  ├─ 不能 → 诚实告知「当前平台只支持表单、管理系统、图表三类，这个需求超出了范围」
  │         → 推荐 record_workspace_event
  │
  ▼ 能
维度二：有现成的工具/库支撑吗？
  ├─ 没有 → 诚实告知「目前没有能实现这个功能的工具或库」
  │         → 看有没有降级方案（如用户要「智能去水印」→ 降级为「裁剪/遮挡水印区域」）
  │         → 推荐 record_workspace_event
  │
  ▼ 有
维度三：复杂度在请求-响应范围内吗？
  ├─ 超出 → 诚实告知复杂度限制
  │         → 推荐 record_workspace_event
  │
  ▼ 在范围内
可以做 → 进入正常流程（读文档 → 出 PRD → 用户确认 → 写代码）
```

## 五、HTML 静态页面（兜底能力）

当需求**无需后台处理**、属于**纯展示**时，可用 **search_tools("html|网页|页面")** 搜 HTML 生成类工具（如 html_generate），用 run_form_submit 调用。生成的是静态 HTML 文件，用户访问即可查看，**不挂在项目树上**，适合一锤子买卖、临时需求。

| 适用 | 不适用 |
|------|--------|
| 静态数据看板、年度报告、会议展示页 | 需要实时变化的数据 |
| 数据已给定或可一次性计算得出 | 需要查库、增删改查 |
| 活动页、展示页、工具页 | 复杂交互、自定义 Canvas/WebGL |

**典型场景**：用户要「做个数据看板」「生成年度报告展示」——若数据是**静态的、一次性的**，用 html_generate；若数据来自 Table、需**实时查库**，用 Chart。

## 六、做不到时怎么回复

1. **诚实说明**：用大白话告诉用户哪个维度过不了，不说技术术语
2. **给降级方案（如果有的话）**：不能只说「做不到」就完了，想想有没有简化版能做。**若需求是纯展示、无后台、数据一次性**，可尝试 search_tools("html|网页|页面") 看能否用 HTML 静态页面兜底
3. **调用 record_workspace_event**：event_type 填 `unsupported_demand`，description 写一句话原因（如「用户需要无痕去水印，平台无对应 AI 模型和工具」）
4. **结束回复**：不要在说完做不到之后又尝试硬写代码

## 七、「动态字段」类需求的边界与降级

### 什么是动态字段需求？

用户希望「在运行时自定义字段、每次字段都不同」的场景。典型：**通用问卷系统**（管理员配置题目，不同问卷字段不同）、自定义审批表单、在线考试系统等。

### 为什么做不了通用版？

平台的 Form/Table 字段在**代码编译时确定**，前端按固定 schema 统一渲染。不支持「根据数据库里的配置动态生成不同字段的表单」。这是架构层面的限制，不是代码层面能解决的。

### 降级方案（可以做！）

| 方案 | 做法 | 适合 |
|------|------|------|
| **每份问卷单独生成一个 Form（或 Form+Table）** | 用户描述「帮我做一份 XX 调查问卷，题目有：1. 姓名（填空）2. 满意度（单选：满意/一般/不满意）3. 建议（填空）」，工作台为这份具体问卷生成一个固定字段的 Form 或 Table，问卷字段直接对应表单字段 | 问卷不多（偶尔做几份），每份字段不同但创建后不变 |
| **管理层用 Table，问卷用第三方工具** | Table 管理问卷元信息（标题、状态、链接、回收量），实际问卷创建和填写用问卷星等专业工具，Chart 做统计 | 问卷量大、需要频繁创建 |

### 遇到此类需求时怎么回复

1. 诚实告知：「做一个像问卷星那样可以随意配置题目的通用问卷引擎，目前平台做不了，因为表单的字段是创建时就确定的。」
2. 给降级方案：「但我可以帮您两种方式处理：① 直接帮您把这份具体的问卷做成一个表单，题目就是固定的字段，填写后数据自动入库；② 如果您需要经常创建不同的问卷，建议用问卷星做问卷，我帮您在这边做个管理台来统一管理和统计。您倾向哪种？」
3. 用户选择后正常执行。

## 八、常见误判提醒

| 容易误判的需求 | 看起来能做？ | 实际分析 |
|----------------|--------------|----------|
| 「做个通用问卷系统」 | Table 管题目 + Form 填问卷？ | ❌ 做不了通用版（需要动态字段渲染）；**降级**：每份问卷单独生成一个 Form/Table（字段固定），或用第三方工具+Table 管理。见上方「动态字段类需求」 |
| 「帮我去水印」 | 像是图片处理，Form 能做？ | 维度二不通过：ImageMagick / GraphicsMagick 只能裁剪/覆盖，无法智能修复；降级方案：裁掉或遮挡 |
| 「做个聊天软件」 | 像是管理系统？ | 维度一不通过：需要实时双向通信，不是 Table/Form/Chart 能承载的 |
| 「做个在线视频编辑器」 | 像是视频处理 Form？ | 维度一+三不通过：需要复杂前端交互 + 实时预览，不是一次提交一次返回 |
| 「接入微信支付」 | 代码里调 API？ | 维度二不通过：平台未对接微信支付 API，无现成工具 |
| 「做个员工管理系统」 | Table！ | ✅ 三个维度全通过，正常做 |
| 「做个定时爬虫」 | 需要持续运行？ | ✅ **能做**。拆解：单次爬取 = Form（Go 的 colly/goquery 或 Python requests + bs4）；数据管理 = Table；定时 = 平台定时任务。三个维度全通过 |
| 「帮我把这个 PDF 转成 Word」 | Form！ | ✅ 有 LibreOffice/Pandoc，正常做 |
| 「做个数据看板/年度报告展示」 | Chart？要建表？ | 数据**静态、一次性** → search_tools("html") 用 html_generate；数据**来自 Table、需实时查库** → Chart |
