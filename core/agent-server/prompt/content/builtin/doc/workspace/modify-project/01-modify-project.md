# 修改项目

当用户要**改已有代码**或**给项目写文档**时，按本文档执行。

---

## 一、修改 PRD（先方案后动手）

不要一上来就改代码。先根据用户需求输出**修改 PRD**，得到用户确认后再执行。

### 修改 PRD 格式

用**用户能看懂的表述**（修改点、在哪个页面/表单/列表、用户会看到什么效果），**禁止**出现文件名（xxx.go）、结构体名（MeetingRoomBookingListReq）等代码词汇。

| 序号 | 修改点 | 在哪儿改 | 用户会看到什么 |
|------|--------|----------|----------------|
| 1 | 预约列表支持按「预约状态」筛选 | 预约列表页面 | 页面上方多一个「预约状态」下拉框，选完后列表只显示该状态的预约 |
| 2 | 会议室增加「容量上限」 | 会议室的新增/编辑表单、列表 | 表单多一项「容量上限」（数字），列表多一列 |

若用户对 PRD 不满意、提出调整，按要求修改后再输出，直到用户确认。

---

## 二、改代码 SOP

确认后按以下步骤执行：

1. **按需读文档**：涉及组件/列表/包约定时 read_doc SDK 或案例（路径见 create-project 文档末尾表格）。
2. **看代码**：`read_go_file` 读取要改的文件，从实际内容中**复制要替换的原文**作为 search_string。
3. **改代码**：**优先 `search_replace_file`**（只改一段，省 token）；仅大改或整文件重构时才用 `write_go_file`。
4. **编译**：改完后调用 `build_workspace`。

### search_replace_file 要点

- `search_string` 必须与文件内容**完全一致**（含空格、制表符、换行），否则替换不生效。
- 使用前**先 read_go_file**，从实际内容中复制原文，不要手敲或猜。
- 只改匹配到的片段，不整文件覆盖。

### 编译失败处理

循环处理直到编译成功：
1. 查看 build_workspace 返回的报错信息。
2. 按需用 `read_go_file_lines(file_name, line_ranges)` 读报错行。
3. 能确定原因 → 直接修复；不能确定 → read_doc SDK 或案例对照排查。
4. 再调 `build_workspace`，失败则重复。

---

## 三、写项目文档

仅当用户**明确要求**写 README/使用说明时：
- `write_doc(name, code, content)`，缺目录先 `create_directory`。
- 完成后简短说明文档位置。
