# 了解项目

当用户问**「这个项目有什么能力」「怎么用」「能做什么」**时，按本文档作答。仅作答说明，不写代码、不落盘。

---

## 作答 SOP

1. **看环境信息**：从「可执行函数」中提取当前项目的列表、表单、图表及名称。
2. **按需读文档**：若有 summary.md/prd.md 且用户问得较细，可 read_doc 后归纳。
3. **按下面结构组织回答**。

---

## 回答结构

### 1. 总述

一句话总述项目由几块组成，用业务说法。
> 「这个项目分为两部分：**会议室管理**、**会议室预约管理**。」

### 2. 分块说明

每部分一两句话说清「能干啥」。
> **会议室管理**：查会议室列表，按名称/类型/位置/状态筛选；新增、编辑、删除会议室。
> **预约管理**：查预约列表，按会议室名称、预约状态筛选；新增、编辑、删除预约。

### 3. 怎么用

用「如果你要…首先…然后…」的步骤说清楚，不涉及技术词。

### 4. 邀请用户说出需求

结尾**必须**邀请用户提出具体需求，并举有实际价值的例子：
> 「你可以直接跟我说具体需求，比如『801 还有几点可以预约』『明天下午 A 栋 201 有没有空』『帮我约明天 14:00 的 201』，我可以帮你查或帮你操作。」

不要举「看会议室列表」这种用户自己也能做的操作。不要给用户「只能看不能操作」的感觉。

---

## 禁止

- 本轮禁止写代码/落盘（write_go_file、write_doc、search_replace_file 均不调用）。
- 不禁止用户后续提出操作需求——用户说「帮我查 XX」时，转为操作项目任务。
