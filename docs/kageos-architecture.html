Kageos Full-Link Architecture Diagrams

Key Principles:
1. api-gateway handles all auth (JWT) and passes trusted headers (X-Request-User).
2. Inter-service calls use `pkg/apicall` and route back through the api-gateway.
3. app-runtime exposes no HTTP API, communicating entirely over NATS.
4. NATS is the central bus for async commands, event broadcasting, and app invocations.

2. Full-Link Chat Request Sequence

How an AI chat message from the user results in tool calls and an SSE token stream.

sequenceDiagram
    actor User
    participant Web as Web (Vue)
    participant GW as api-gateway :9090
    participant AgentSrv as agent-server :9095
    participant LLM as External LLM API
    participant AppSrv as app-server :9091
    participant AppRuntime as app-runtime (NATS)
    participant NATS as NATS Bus

    User->>Web: POST /agent/api/v1/workspace/chat/stream
    Web->>GW: HTTP POST (X-Token: JWT)

    Note over GW: Validate JWT\nInject X-Request-User header\nAdd TraceId

    GW->>AgentSrv: proxy /workspace/chat/stream (SSE)

    AgentSrv->>LLM: Stream LLM tokens
    LLM-->>AgentSrv: token stream

    loop Agent Tool Calls
        AgentSrv->>GW: REST GET /workspace/api/v1/service_tree/detail
        GW->>AppSrv: proxy
        AppSrv-->>GW: data
        GW-->>AgentSrv: JSON

        AgentSrv->>GW: REST POST /workspace/files/write
        GW->>AppSrv: proxy
        AppSrv->>NATS: Publish runtime.v1.cmd.file.write
        NATS->>AppRuntime: QueueSubscribe
        AppRuntime-->>NATS: reply OK
        AppSrv-->>GW: OK
        GW-->>AgentSrv: OK
    end

    AgentSrv-->>GW: SSE stream chunks
    GW-->>Web: SSE stream
    Web-->>User: Real-time text display

3. App Build & Container Reload Flow

How agent-server modifying code triggers an app container rebuild in app-runtime.

sequenceDiagram
    participant AgentSrv as agent-server
    participant GW as api-gateway
    participant AppSrv as app-server
    participant NATS as NATS Bus
    participant AppRuntime as app-runtime

    AgentSrv->>GW: POST /workspace/api/v1/app/update
    GW->>AppSrv: proxy

    AppSrv->>NATS: Publish runtime.v1.cmd.app.update
    NATS->>AppRuntime: HandleAppUpdate
    AppRuntime->>AppRuntime: Rebuild & reload app container

    AppRuntime->>NATS: Publish runtime.v1.event.lifecycle.*
    AppSrv-->>GW: 200 OK (build enqueued)
    GW-->>AgentSrv: OK

    Note over AppRuntime: App container now live

4. Function Invocation Flow (Table/Form)

How the frontend executing an app function routes all the way to the Python/JS sandbox.

sequenceDiagram
    actor User
    participant Web as Web
    participant GW as api-gateway
    participant AppSrv as app-server
    participant NATS as NATS Bus
    participant AppRuntime as app-runtime
    participant App as App Container (Python/JS)

    User->>Web: GET /workspace/api/v1/table/search/...
    Web->>GW: HTTP (JWT)
    GW->>AppSrv: proxy /workspace/*

    AppSrv->>NATS: Publish runtime.v1.cmd.app.invoke... (request-reply)
    NATS->>AppRuntime: QueueSubscribe
    AppRuntime->>App: Forward invoke to app process

    App-->>AppRuntime: result
    AppRuntime-->>NATS: Reply
    NATS-->>AppSrv: Result received

    AppSrv-->>GW: JSON response
    GW-->>Web: JSON
    Web-->>User: Render Table
