# 工作台最新设计

当前工作台采用“单 Dev 模式 + 角色状态机”。

## 主链路

```text
用户输入
-> router 判断目标角色
-> product_manager 设计并输出结构化 PRD
-> 用户确认 PRD
-> app_developer 按 PRD 创建应用并 build
-> qa_engineer 验证核心功能
-> maintenance_engineer 或 build_engineer 处理问题回流
```

## 角色边界

- `product_manager`：分析新应用需求，输出 `write_prd`，等待确认。
- `app_developer`：按已确认 PRD 写 Go 文件、创建目录、build。
- `qa_engineer`：调用运行工具验证 Table/Form/Chart。
- `maintenance_engineer`：修改已有应用、字段、选项、回调、消息、图表和业务 bug。
- `build_engineer`：修复构建、schema、widget、SDK API 问题。
- `data_operator`：处理一次性文件、媒体和数据任务。
- `platform_engineer`：处理平台 OpenAPI、消息、权限、审计。
- `reviewer`：只读分析、解释和代码审查。

## 上下文策略

阶段交接不携带完整旧会话，只携带 artifact、摘要、目录、关键文件、路由、构建结果、测试结论和已知问题。
