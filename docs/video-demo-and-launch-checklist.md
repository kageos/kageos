# Kageos 视频演示链路与发布前验收清单

> 状态：宣传与录制前验收草案
> 日期：2026-07-06

本文用于统一 Kageos 后续录制视频、官网/社媒宣传、早期用户推广和发布前质量验收。核心目标是：把已经具备的主要能力整理成能讲清、能演通、能复测的主链路；把仍在建设中或路线储备的能力明确标出来，避免对外承诺超出当前交付状态。

## 总原则

- 先演已上线主链路，再讲路线图。不要把 Hub、workflow、通用审批、评论评分等未完整交付能力混进当前主卖点。
- 每个视频只围绕一条主线：安装、自托管、目录、人机双入口、AI 工作台、无人值守 Agent、消息与治理。
- 每个口播主张都要能落到一个可重复的演示步骤。录制前按本文 P0 清单完整跑一遍。
- 演示数据要干净、可重置、无真实密钥、无客户数据、无本地私有路径暴露。
- 演示环境不要靠手工改库、临时 patch、隐藏脚本或只在某台机器上存在的配置支撑。
- 对外统一使用“源码公开、可自托管；当前采用 BSL 1.1，四年后转 Apache-2.0”，不要说成 OSI open source。

## P0 必须稳定链路

P0 是视频和早期推广前必须保证稳定的主链路。任何一条 P0 不能稳定复现，都不建议录对应视频。

| 链路 | 口播主张 | 演示步骤 | 通过标准 | 常见风险 |
| --- | --- | --- | --- | --- |
| 安装与登录 | Kageos 可以源码公开、自托管、本地启动。 | `git clone`，`go run ./cmd/kagectl bootstrap --dev`，进入 `web` 执行 `npm install && npm run dev`，打开 `http://localhost:5173`，用 `system` 登录。 | 后端启动无阻塞错误；前端可打开；system 用户可登录；本地验证码/密码说明清晰。 | 依赖版本不匹配、Podman/Docker 不可用、端口冲突、首次启动日志信息不清晰。 |
| Service Tree 与目录 | Kageos 把能力挂到统一 Service Tree 上治理。 | 打开工作区，查看目录树，进入一个目录，展示 Form/Table/Chart/Docs 和路径。 | 目录能加载；资源能点击；路径清晰；不存在空白页或加载死循环。 | 前端路由状态丢失、树节点统计不刷新、资源名称和路径展示不友好。 |
| Form/Table/Chart/Docs | 目录资源既是 UI，也是 AI 可理解的 schema 能力。 | 在 Web UI 里提交一个 Form，查询一个 Table，打开一个 Chart，阅读一个 Docs。 | 表单提交有结果；表格查询稳定；图表不空白；文档可读且资源引用能跳转。 | 字段渲染异常、文件上传/下载失败、图表空数据、文档链接失效。 |
| 人机双入口 | 同一个能力，人能使用，AI 也能调用。 | 在 UI 中操作同一资源；再让 AI 工作台调用对应 Form/Table/Chart。 | AI 能找到资源；工具调用参数符合 schema；结果能回显或写回。 | AI 上下文找不到资源、schema 描述不清、工具结果格式不稳定。 |
| AI 工作台开发 | AI 可以在目录上下文中写 PRD、改代码、build、修复和验证。 | 进入一个目录，发起工作台会话，让 AI 做一个小改动，执行 build/update，再运行验证。 | 文件修改范围合理；build 成功；功能在 UI 或工具调用中可验证。 | 生成伪代码、修改无关目录、build 报错无法自修、前端状态未刷新。 |
| 应用运行时 build/update | 目录代码变更可以发布为新的运行版本。 | 修改一个已存在目录能力，执行 build/update，刷新资源并调用新能力。 | 新版本生效；旧版本不影响当前调用；错误日志可定位。 | SDK 版本不一致、容器启动失败、旧版本清理或运行态发现异常。 |
| 定时函数任务 `app.function` | 固定函数可以按计划自动执行。 | 创建或打开一个函数任务，设置执行时间，等待触发或手动 run now，查看执行记录。 | 任务能创建、暂停、恢复、立即执行；执行记录状态正确。 | 调度时间解释不清、租约/heartbeat 状态异常、执行失败但 UI 不可见。 |
| Agent 任务 `agent.session` | 无人值守 Agent 可以按计划执行 SOP。 | 配置 runbook 或任务说明，创建 Agent 任务，触发执行，查看工作台会话和结果。 | 会话创建成功；Agent 能读取上下文；结果有记录；失败时有可理解的错误。 | 任务说明过于模糊、Agent 无法闭环、通知对象缺失、执行时间过长。 |
| 消息与站内信 | 自动执行结果可以沉淀到站内信和来源路径。 | 由业务函数或 Agent 发送通知，打开站内信列表、详情和来源跳转。 | 消息落库；未读数更新；source path、附件和跳转正常。 | 消息投递失败、附件无法预览、来源路径跳不到对应目录。 |
| 操作日志与 trace | AI 和自动化可以执行，但必须有治理记录。 | 对一次表单调用、一次 AI 调用、一次定时执行展示日志、trace 或执行记录。 | 能看出谁在何时通过什么来源执行了什么动作；错误可排障。 | trace 丢失、日志字段缺上下文、前端入口藏得太深。 |

## P1 增强可信度链路

P1 不一定要放进第一批视频，但会明显提升可信度。建议在 P0 稳定后逐个补演示材料。

| 链路 | 价值 | 验收重点 |
| --- | --- | --- |
| 能力包导入导出 | 证明目录能迁移、复用和分发。 | 导出 bundle、导入到另一个 namespace、资源和函数可用。 |
| 生产安装与更新 | 证明不是只能本地开发。 | `install.sh`、生产 compose、`kageos update`、数据保留和版本可查。 |
| 外部 webhook 摘要通知 | 证明站内信之外也能触达。 | 外部卡片有摘要、能跳回 Kageos 查看完整详情。 |
| 权限与成员边界 | 证明 Service Tree 不只是导航。 | 不同用户访问同一目录资源时权限行为符合预期。 |
| runbook.docs | 证明 Agent 有业务上下文，不是裸 prompt。 | 工作台上下文能读到当前目录 runbook，资源引用清晰。 |
| 官方系统工具目录 | 证明平台能内置可运行能力。 | 文件处理、PDF、表格、图片等系统工具能打开并完成一个简单任务。 |

## P2 只讲路线，不做当前交付承诺

这些能力可以放在路线图页、视频结尾或投资人/客户沟通中，但不建议在当前主视频里现场演成“已经完整可用”。

| 能力 | 推荐说法 |
| --- | --- |
| Hub 公共目录市场 | Hub 是后续目录分发和在线试用的建设方向。当前可以先展示能力包和内置种子目录。 |
| workflow 图和 `workflow.run` | 当前已有函数任务和 Agent 任务，通用 workflow 编排属于路线储备。 |
| 通用审批 | 当前有权限、操作日志和任务记录；通用审批后续作为高风险动作治理层补齐。 |
| 评论、评分、点赞 | 当前不作为核心卖点，后续用于目录质量反馈和生态治理。 |
| 企业私有 Hub、SSO、SLA | 属于商业版和企业增强路线，可在商务沟通中按需求展开。 |
| 备份控制面 | 当前强调自托管和数据目录，完整备份控制台后续补齐。 |

## 录制前验收流程

### 环境准备

- 使用干净的 demo 账号、demo namespace 和 demo 数据。
- 记录当前 Git commit、镜像版本、SDK 版本和本地依赖版本。
- 关闭或脱敏真实 LLM key、webhook URL、客户数据和私有路径。
- 准备一个可重复的业务场景，不要每次录制临场生成随机需求。

### 三轮 dry run

| 轮次 | 目标 | 通过标准 |
| --- | --- | --- |
| 第 1 轮：开发环境 dry run | 发现明显 bug 和脚本缺口。 | P0 链路能跑通，失败点都记录到修复清单。 |
| 第 2 轮：准录制环境 dry run | 验证画面、数据、账号、网络和性能。 | 不需要手工改库或临时修代码，画面稳定，关键步骤 1 次成功。 |
| 第 3 轮：正式彩排 | 按视频脚本完整演一遍。 | 口播、点击路径、等待时间、错误兜底都明确，适合开始录制。 |

### 失败处理规则

- P0 失败：暂停录制，先修功能或改脚本范围。
- P1 失败：可以暂时移出视频，不影响主线时只记录为后续补强。
- P2 未完成：不要尝试临时演示，统一用 Roadmap 口径表达。
- 如果某条链路需要复杂前置条件，必须写进视频脚本或拆成单独技术视频。

## 第一支总览视频脚本骨架

1. 开场：AI 生成工具很多，但企业真正缺的是可安装、可运行、可治理、可复用的能力目录。
2. 一句话定位：Kageos 是源码公开、可自托管的 AI 原生业务目录平台。
3. 打开平台：展示登录后的工作区和 Service Tree。
4. 展示目录：一个目录里有 Form/Table/Chart/Docs/Function，不是孤立页面。
5. 人机双入口：人在 UI 里提交表单，AI 工作台调用同一个能力。
6. 自动化：展示定时任务或 Agent 任务，说明无人值守执行后会写回记录并发通知。
7. 治理：展示操作日志、trace、站内信或执行记录。
8. 边界：当前已支持自托管、目录、工作台、定时 Agent 和消息；Hub、workflow、通用审批在路线图中。
9. 结尾：邀请开发者自托管试用、反馈场景、一起完善目录生态。
