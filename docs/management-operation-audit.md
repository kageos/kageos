# 管理操作日志

以下操作统一进入现有 `operate_logs`：

| 操作 | action | 主要内容 |
| --- | --- | --- |
| 定时任务创建、修改、暂停、恢复、取消、删除、立即执行 | `timer.task.created/updated/paused/resumed/cancelled/deleted/run_now` | 操作人、资源路径、调度和状态前后值、执行身份、参数指纹、关联执行 ID |
| 工作空间删除 | `workspace.deleted` | 删除前名称和版本、运行时删除/工作空间记录删除的完成情况、失败阶段 |
| 目录安装和覆盖安装 | `directory.installed` | 安装来源、包内容 SHA-256、包版本、目标、覆盖选项、已确认路径、响应数量、版本变化、告警 |
| 目录复制和替换 | `directory.copied` | 源/目标路径、替换选项、结果数量、版本变化 |
| 公开分享创建、关闭 | `public_share.created/disabled` | 内部记录 ID、标题、有效期、次数限制、启用状态前后值 |

工作空间或目录的操作日志可查看所属资源的记录；“系统设置 → 操作历史”使用系统管理员专属的全局查询，包含已经删除的工作空间。全局查询显式使用 `resource_path_prefix=/`，仅允许 `system`。其他查询继续走资源读取权限。全局视图不提供每日定时执行分组。

## 可靠性和结果含义

- 定时任务管理操作和审计发送事件在同一个数据库事务内提交；写入事件失败时业务变更回滚。失败操作另记失败事件，不能把未提交的请求当成已生效状态。
- 使用已有 `timer_outbox_event` 向内部 NATS subject `platform.timer.audit.record` 投递。app-server 落盘成功后才返回确认；未确认时持久重试。`operate_logs.event_id` 是新增的可空唯一字段，由现有 AutoMigrate 添加；已有行保留 NULL。在线日志通过事件 ID 去重，并使用事件发生时间，不使用投递时间。迁移应先于接收审计事件；接收方不可用期间事件保留在 timer 队列。
- 普通执行事件优先发送；每轮最多尝试一个管理审计事件，避免接收方故障阻塞整批执行消息。定时任务的普通执行记录沿用原链路。
- 删除、安装、复制和分享管理先同步记录 `pending`，再执行操作，最后同步更新同一条记录。进程中断留下“结果待确认”，不假报成功。正常失败记录停留阶段及已知完成情况；结果记录失败会返回包含审计 ID 的错误，初始记录仍保留。它们不是跨服务分布式事务，不能仅从 failed 推断已经回滚。
- `run_now` 成功表示已创建执行记录，并不表示业务执行成功；最终结果查看关联 execution ID。安装响应中的目录/文件数量是本次处理数量，不直接解释为新增数量；`overwrite=true` 是允许覆盖，不代表全部资源都已覆盖。
- 重复创建相同幂等任务、未变化的配置以及重复关闭已经关闭的分享不增加成功日志。定时任务没有工作空间资源路径时归入系统历史。

## 数据范围

不保存公开访问凭证、安装密钥、签名下载 URL、完整源码或执行参数正文。参数和任务元数据只保存 SHA-256，用于判断是否改变；文档/源码内容仍由对应版本机制管理。安装来源仅保存远端 origin，包内容指纹基于解析后重新编码的 bundle JSON，不冒充原始下载文件的字节哈希。

系统历史是对已有日志的统一查询，不补造历史操作。全局视图受现有在线保留和归档策略约束；它不是永久在线存储。

## 验证

测试覆盖任务变更与审计的事务一致性、失败状态、幂等创建、持续重试、接收去重、发生时间、分享凭证排除、下载失败脱敏、删除后日志保留、全局查询权限，以及前端前后值和待确认/失败展示。
