# AI-Agent-OS 项目简报与出海目标

> 用途：给其他 AI 模型、顾问、潜在合作者或内部成员快速理解项目、定位、优势、目标市场和下一步规划。  
> 状态：战略讨论稿，不等同于已发布官网文案。  
> 更新时间：2026-05-19

## 1. 项目一句话

AI-Agent-OS 当前应重新定位为：

> 一个开源轻应用工作台。用户可以在一个统一 workspace 中安装、复制、分发和用 AI 修改各种轻量业务应用，例如工单、问卷、投票、库存、CRM Lite、文件转换和数据分析工具。

它不应该被包装成“大而全企业 Agent OS”，而应该聚焦于：

> 用一个统一工作台替代一堆分散的小 SaaS 工具。

英文方向可表达为：

> Open-source workspace for installable lightweight business apps.

## 2. 项目本质

AI-Agent-OS 不是单纯聊天机器人，也不是一次性代码生成器。

它的核心是把小团队常见的业务需求收敛为可运行、可复用、可分发的轻应用：

- Form：表单、上传、提交、转换、一次性工具。
- Table：台账、工单、客户、库存、招聘、任务、CRUD 管理系统。
- Chart：统计、仪表盘、问卷结果、运营分析。
- Service Tree：统一组织所有应用、目录和函数。
- 统一工作台：用户在同一个 workspace 中打开、运行、修改应用。
- AI 工作台：通过自然语言生成、修改、修复和验证轻应用。
- 能力包：已有 capability bundle 雏形，可导出/导入应用目录和代码，未来可升级成应用包市场。

## 3. 解决的问题

海外小团队和中小企业经常遇到以下问题：

- 为每个小需求单独买一个 SaaS：工单、问卷、投票、表格、文件转换、数据分析、库存、CRM 等。
- 每个 SaaS 都有一套账号、权限、订阅费、数据和后台。
- 员工入职/离职时要处理一堆账号。
- 数据分散在 Google Sheets、Airtable、Notion、Slack、各种在线工具里。
- 小业务系统找工程师开发太贵，买大平台又太重。
- 现有低代码工具通常需要用户自己搭建界面、数据源和逻辑，普通业务人员仍然有门槛。

AI-Agent-OS 的目标是：

> 让小团队用一个登录、一个工作台、一个应用市场，管理和运行很多小业务系统。

## 4. 产品差异化

### 4.1 不是 builder，而是 installable apps

Retool、Appsmith、Budibase 更像 internal tool builder。  
n8n、Zapier、Make 更像 workflow automation。  
Airtable、Notion、Google Sheets 更像灵活数据表和协作空间。

AI-Agent-OS 应该强调：

> 用户不需要从空白页面开始搭建，而是先安装一个能跑的轻应用，再按自己的业务用 AI 修改。

例如：

- 安装 Ticket Tracker。
- 说一句“加一个 SLA 字段，并按逾期状态生成统计图”。
- 系统修改应用代码、构建、注册并让用户继续使用。

### 4.2 统一工作台，而不是多个 SaaS

用户可以把多个小系统放进同一个 workspace：

- 工单系统。
- 问卷系统。
- 投票系统。
- 文件转换工具。
- CSV/Excel 分析工具。
- 资产管理。
- CRM Lite。
- 员工离职账号清理工具。

这些应用共用：

- 统一登录。
- 统一工作空间。
- 统一服务树。
- 统一文件上传和输出。
- 统一表格和图表渲染。
- 统一运行时。
- 统一应用包导入导出。

### 4.3 AI 的价值在“安装后修改”

相比“从零生成应用”，更现实的用户路径是：

1. 从应用库安装一个现成应用。
2. 用示例数据立即体验。
3. 用自然语言做小改动。
4. 复制成团队自己的版本。
5. 继续沉淀为新的应用包或行业套件。

这比普通模板市场更有价值，因为模板最大痛点是“不完全适合我”。

## 5. 适合做的轻应用品类

第一阶段应优先做官方精选应用，而不是开放大市场。

### 5.1 管理类

- Ticket Tracker / 工单管理。
- CRM Lite / 客户跟进。
- Inventory Tracker / 库存台账。
- Asset Manager / 资产管理。
- Recruiting Tracker / 招聘候选人管理。
- Project Task Tracker / 项目任务。
- Purchase Request / 采购申请。

### 5.2 表单互动类

- Survey Builder / 问卷系统。
- Poll System / 投票系统。
- Feedback Collector / 反馈收集。
- Registration Form / 活动报名。
- Internal Request Form / 内部申请表。

### 5.3 文件与数据工具类

- PDF Tools / PDF 转换、合并、压缩、水印。
- Image Compressor / 图片压缩。
- OCR Extractor / OCR 提取。
- CSV Cleaner / CSV 清洗。
- Excel Analyzer / Excel 分析。
- Invoice Extractor / 发票信息提取。
- Batch Rename / 批量重命名。

### 5.4 分析类

- Survey Analysis / 问卷结果分析。
- Customer Feedback Analysis / 客户反馈分析。
- Sales CSV Analysis / 销售数据分析。
- Support Ticket Classification / 客服工单分类。
- NPS Analysis / NPS 分析。

### 5.5 垂类工具

- 物业报修。
- 维修工单。
- 门店巡检。
- 民宿清洁排班。
- 教培报名。
- 小诊所随访。
- 宠物店预约。
- 外贸客户跟进。

## 6. 海外目标用户

第一阶段不应面向大企业采购，而应面向：

- 10-100 人的小公司。
- 没有专职 IT 的小团队。
- Agency、顾问、外包团队。
- Self-hosted 和开源用户。
- 运营、行政、HR、客服、销售支持团队。
- 有大量 Excel、Google Sheets、Airtable、Notion 和小 SaaS 混用问题的团队。

暂时不建议直接主攻：

- 金融、医疗、政府等强合规行业。
- 大企业 IT 采购。
- 需要完整 SSO、SCIM、SOC2、复杂 RBAC 和审计体系的客户。

## 7. 商业模式

项目可以同时支持开源 self-hosted 和 hosted SaaS。

### 7.1 开源社区版

作用：传播、获客、建立信任。

包含：

- 基础工作台。
- Form/Table/Chart。
- 基础应用安装。
- 单机部署。
- 少量官方应用包。
- 基础用户登录。

### 7.2 Hosted Cloud

作用：主要订阅收入。

适合不想部署的小团队。

可能定价：

- Starter：$29/month。
- Team：$99/month。
- Pro：$199/month。

### 7.3 Self-host Pro

作用：高客单价收入。

收费能力可包括：

- OIDC/SSO。
- RBAC。
- 操作日志和审计导出。
- 备份恢复。
- 多 workspace。
- 私有应用市场。
- 高级连接器。
- 商业支持。

可能定价：

- Team Self-host：$999/year。
- Business Self-host：$2,999/year。
- Enterprise：$8,000+/year。

### 7.4 官方应用包和行业套件

单个应用包：

- $49-$199。

场景套件：

- Operations Pack。
- HR Pack。
- Agency Pack。
- File Tools Pack。
- E-commerce Ops Pack。

价格：

- $499-$1,999。

### 7.5 部署和定制服务

早期现金流可来自：

- 部署协助。
- 数据迁移。
- 应用包定制。
- 连接器开发。
- 私有化支持。

价格可从 $500 到 $20,000 不等，关键是每次定制都尽量沉淀为可复用应用包。

## 8. 当前短板

项目目前不应声称 enterprise-ready。

关键短板包括：

- 英文 UI、文档、官网和 demo 不完整。
- SSO/OIDC、SAML、SCIM 尚未完善。
- RBAC 权限体系不完整。
- 操作日志和审计能力需要补齐。
- 应用包市场还未产品化。
- 官方应用包数量和质量不足。
- 海外连接器不足，例如 Google Workspace、Slack、Zoom、GitHub、Notion、Airtable、Postgres、S3。
- 部署体验需要极简化。
- 安全、隐私、数据删除、DPA、合规文档需要补。

## 9. 最小出海版本目标

第一阶段目标不是做大平台，而是让海外用户 5 分钟内理解并跑起来。

必须具备：

- 新品牌名。
- 英文 README。
- 英文官网。
- Docker 一键启动。
- 在线 demo。
- 应用市场页面。
- 12 个高质量官方应用。
- 应用安装、复制、导出、导入。
- 应用详情页：截图、说明、示例数据、权限声明。
- AI 修改示例：加字段、改状态、加图表、改导出。
- 基础登录。
- 基础操作日志。
- 至少说明当前适合 individuals and small teams。

## 10. 90 天路线

### 第 1-2 周：定位和包装

- 确定新名字。
- 重写英文 README。
- 做官网 landing page。
- 明确一句话定位。
- 准备 Docker 一键启动。
- 准备 3-5 个 demo 应用。

- 准备安装体验。
- 录制短视频。

### 第 7-8 周：海外发布

- GitHub 发布。
- Product Hunt。
- Hacker News。
- Reddit r/selfhosted。
- Indie Hackers。
- X/Twitter。

### 第 9-12 周：付费验证

- 找 20 个海外 design partners。

## 11. 关键判断

### 11.1 海外是否有机会

有机会，但不能卖成“企业 Agent OS”。

更适合的方向是：

> open-source lightweight app workspace + installable app marketplace + AI customization.

海外用户已经接受模板、应用市场、自部署和 SaaS 订阅。n8n、Retool、Appsmith、Airtable 等都证明了相关需求存在。

### 11.2 国内和国外哪个更好赚钱

- 国内更容易拿第一笔钱，但容易变成定制外包。
- 国外更适合产品化订阅和开源传播，但冷启动难度更高。

建议：

> 国内验证场景，国外主攻产品化商业化。

### 11.3 是否需要公司

早期可以先不开公司，用个人身份和 MoR 支付工具验证需求。  
有稳定收入、需要签合同、开票、合规、DPA 或企业客户时，再注册公司并规范税务。

### 11.4 Self-hosted 怎么赚钱

免费开源版负责获客。  
收费来自：

- Hosted Cloud。
- Self-host Pro license。
- 官方应用包。
- 行业套件。
- 部署支持。
- 定制服务。
- 商业支持。

## 12. 给其他模型的分析任务

如果把这份文档交给其他模型，可以要求它帮助分析：

1. 这个出海定位是否足够清晰。

3. 第一批 12 个官方应用应该如何排序。
4. 哪些应用最适合 SEO 获客。
5. 哪些功能是出海前必须补的。
6. 开源版和商业版边界怎么划分。
7. 定价是否合理。
8. 如何设计官网首屏文案。
9. 如何设计 Product Hunt / Hacker News 发布文案。
10. 如何避免项目被定制需求拖成外包公司。

中文：

> 一个开源轻应用工作台。  
> 一个登录，一个 workspace，安装和运行工单、问卷、投票、文件工具、数据分析等轻应用。  
> 从应用库开始，用 AI 按自己的业务修改。

> An open-source workspace for installable lightweight business apps.
