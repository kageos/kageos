WORKBENCH

工作台不是聊天框，是企业应用的生成与执行中枢

创建系统时先读边界、SDK 和案例，先 PRD 后落盘；执行任务时直接调用已注册函数，查表、提交表单、查图表都走结构化工具。

生成应用闭环

适合“做一个 XX 系统”“加一个 XX 管理”等需要落代码的企业应用需求。

1
判断能不能做 先判断平台侧还是应用侧，再映射到 Form / Table / Chart。
2
读 SDK 与案例 工单、招聘、会议室、投票、收银台、PDF、视频等案例作为生成参照。
3
PRD 确认后再写代码 字段、列表、业务规则、是否新建目录都明确后再落盘。
4
编译、执行、验证 生成后调用可执行函数验证，失败继续修，直到能用。

执行任务闭环

适合“查一下数据”“提交这个表单”“把视频转成 MP4”“生成一张折线图”等即时任务。

1
先看当前目录能力 当前目录已有 Form/Table/Chart，直接拿 full_code_path 执行。
2
没有就 search_tools 按“视频、PDF、OCR、Excel、Graphviz、Matplotlib”等关键词搜索已注册工具。
3
按 schema 填参数 Form 用 run_form_submit，Table 用 run_table_search/create/update，Chart 用 run_chart_query。
4
结果直接返回 文件、文本、表格、图表都能作为结构化结果交给用户。

BEST PRACTICES

把真实组织需求，变成可运行、可治理、可复用的系统

下面是推荐放进官网和演示视频里的场景脚本。重点不是“AI 会回答”，而是“需求变成了企业软件资产”。

某市政府：百姓呼声工单管理系统

“需要一个百姓呼声系统，群众提交诉求，按民生、交通、医疗、就业分类，流转到部门，统计办结率和满意度。”

Table 工单 Chart 办结统计 权限审批
演示口径：约 2 分钟后生成工单列表、分类筛选、办理进度、部门字段、满意度评分与统计图。

连锁门店：收银台与库存联动

“门店需要商品、会员、支付记录，收银时选择商品和会员，自动计算折扣，扣库存，出销售统计。”

Table + Form + Chart 事务联动 销售趋势
生成商品表、会员表、支付流水、收银台表单、折线图、饼图与仪表盘；流水表默认只读。

人社部门：招聘投递系统

“发布岗位，候选人投递简历，HR 按职位、部门、状态筛选，职位列表可以跳转投递。”

多 Table 文件上传 关联跳转
生成职位表、简历表、投递状态、简历附件、OnSelectFuzzy 选择职位与岗位详情跳转。

机关单位：会议室预约管理

“会议室要能维护容量和设备，预约时只能选择可用会议室，不能时间冲突，能看预约状态。”

主从表 冲突校验 时间状态
生成会议室管理、预约管理、可用会议室下拉、冲突检测、待开始/进行中/已结束计算字段。

办公室：PDF、Excel、视频处理工具箱

“帮我合并 PDF，读取 PDF 内容，把视频转成 MP4，把 Excel 生成图表。”

search_tools run_form_submit 文件返回
不需要临场写脚本，搜到已有工具后按参数执行；FFmpeg、Poppler、LibreOffice、Pandas 等可直接使用。

企业内控：投票与意见征集

“做一个投票系统，主题有开始结束时间，用户只能投一次，多选选项随主题联动。”

Table + Form 依赖下拉 结果统计
生成主题、选项、投票记录、提交投票、查看结果；按时间计算未开始/进行中/已结束。

TOOL NETWORK

别人让 Agent 猜命令，我们让工作台调用标准能力

视频转码、PDF 提取、图片处理、OCR、Excel 解析、Graphviz 流程图、Python 数据分析，这些高频杂活都可以沉淀成带 schema 的 Form 工具。

当前目录没有能力时，工作台会全局搜索工具或能力包模板；搜到后直接执行，搜不到再进入创建流程，把新能力沉淀下来。

通用 Agent
  • 临场判断工具
  • 临场拼命令
  • 参数容易猜错
  • 结果形态不稳定
AI-Agent-OS 工作台
  • 搜索已注册函数
  • 按 schema 填参数
  • 结构化执行与返回
  • 可复制、可发布、可编排

PLATFORM CAPABILITIES

少发明页面，多沉淀标准能力

平台不追求把所有东西做成复杂软件，而是把企业高频需求压缩到几个稳定抽象里。

Form：一次提交，一次结果

文件转换、报告生成、数据解析、图表生成、API 调用，都可以做成带参数和响应的标准工具。

Table：管理一批业务记录

工单、客户、订单、库存、招聘、会议室预约，天然适合用表格管理、筛选、增删改查。

Chart：业务数据直接可视化

折线图、柱状图、饼图、仪表盘，把业务表里的数据变成可查询的统计视图。

平台横切能力内置

权限、操作日志、文件和运行时治理由平台统一提供，业务代码只关心字段和规则。

ServiceTree 统一组织

目录既是代码 package，也是菜单、权限、API 与能力搜索的统一边界。

能力包让应用可复用

好用的目录可以导出、导入和更新，企业不必每次从零开始生成。

RUNTIME

从自然语言到可运行系统，平台链路完整闭环

不是“生成一段代码”就结束。AI-Agent-OS 把应用注册、运行、调用、文件、日志和版本全部接起来。

Web 工作台 服务树、动态 UI、对话、文件上传、Form/Table/Chart 渲染。
agent-server 会话、LLM、工具注册、PRD、代码读写、工具调用编排。
app-server 应用、服务树、函数元数据、Docs、权限与历史。
app-runtime 容器化应用、版本发布、NATS 调用、优雅关闭。
Capability Bundle 目录导出、导入、版本更新、模板复用与能力沉淀。

GOVERNANCE

ToB 不是炫技，能治理才敢用

生成出来的应用自动进入平台治理面，避免每个小系统都重新做一套权限、日志和文件管理。

权限继承

按 full_code_path 管控资源，目录权限向下继承，适合总部、区域、门店等多级组织。

操作记录

谁在什么时候做了什么，平台统一记录，不需要每个业务应用重复造审计表。

容器隔离

每个应用独立运行，版本发布、启动确认、旧版本清理和优雅关闭由 runtime 管理。
