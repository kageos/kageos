# 方案案例：智能会议室预约管理

## 解决什么问题

会议室不是简单台账，它的核心问题是资源占用冲突和运营效率：谁能订、什么时候可用、容量够不够、会前是否提醒、哪些楼层紧张、哪些会议室长期空置。

这个方案把会议室从“列表”变成“可运营资源池”：人可以查空闲和预约，系统可以自动提醒，定时会话可以每天分析使用率并推送日报。

## 推荐目录能力

| 能力 | 类型 | 作用 |
| --- | --- | --- |
| 会议室台账 | Table | 管理会议室名称、位置、楼层、容量、设备、状态 |
| 预约记录 | Table | 管理会议主题、会议室、开始时间、结束时间、预约人、参会人 |
| 查询空闲会议室 | Form | 输入时间、人数、设备需求，返回可用会议室和一键预约链接 |
| 会前提醒巡检 | Form + 默认调度 | 每隔几分钟扫描即将开始且未提醒的会议，发送站内信 |
| 使用率日报 | 定时会话 | 每天统计前一天预约、空置、楼层紧张度、热门时段并推送报告 |
| 使用趋势图 | Chart | 展示按日、按楼层、按会议室类型的使用趋势 |

## 关键业务设计

- 预约状态不一定要落库，可由当前时间和开始/结束时间计算：待开始、进行中、已结束。
- 预约新增和更新必须校验时间冲突、容量、会议室状态；更新时要排除当前记录。
- 删除会议室前检查未结束预约，存在预约时建议改为停用或维护中。
- 参会人为空时可默认预约人；参会人数由参会人列表计算，避免手填不一致。
- 会前提醒要有幂等标记，例如 `reminder_sent`，发送前先 claim，发送失败再释放。
- 查询空闲不是单纯查会议室表，而是先查占用时间段，再排除冲突资源。

## 无人值守怎么做

固定提醒适合写成 `FormTemplate.Schedules`：例如每 2 分钟扫描未来 5 分钟内即将开始的会议。这类任务逻辑稳定、输入固定、适合跟随应用发布自动同步。

日报分析适合写成无人值守定时会话：它可以读取预约表和会议室表，按昨天的时间范围统计总场次、热门时段、预约人 TOP、会议室 TOP、楼层使用率、容量压力和空置率，最后通过站内信发送 Markdown 报告。

这两种自动化可以并存：FormSchedule 负责实时业务提醒，定时会话负责跨表分析和运营建议。

## 模型应该学到的格局

不要只生成“会议室表 + 预约表”。一个真正有用的方案应该让办公室行政、团队成员和管理者都受益：

- 员工少点来回沟通，直接查空闲并预约。
- 行政能维护资源、处理停用和设备信息。
- 系统能主动提醒，减少迟到和忘会。
- 管理者能看到楼层紧张、空置浪费、容量错配。
- 后续还能扩展访客登记、茶歇申请、会议纪要、投屏设备报修。
